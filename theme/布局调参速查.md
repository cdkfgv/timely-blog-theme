# 布局调整速查表（Tailwind v4 构建链路）

预览地址：http://localhost:4321/share/

---

## ⚡ 改样式怎么生效（先看这个）

| 你改的是 | 要跑 build 吗 | 要重启实例吗 | 生效方式 |
|---|---|---|---|
| EJS 里的 **class**（如 `max-w-[98rem]`） | ✅ 要 | ❌ 不要 | `npm run build` → 刷新浏览器（强刷） |
| `src/input.css`（手写样式 / `:root` 变量） | ✅ 要 | ❌ 不要 | 同上 |
| EJS 里的**结构/文案**（不涉及新 class） | ❌ 不要 | ❌ 不要 | 直接刷新 |
| `dev/src/render.js` 等读取逻辑 | — | ✅ **要** | ES module 缓存，必须重启 |

**三个关键点：**
1. **默认不会自动编译** —— 只有 `build`（一次性）或 `dev`（常驻监听）两种方式；
   两个都不跑，改了 class / input.css 也不会进产物。
2. **不用重启实例** —— dev 预览服务的 `/theme/*` 路由每次请求实时读盘，CSS 改完刷新页面就是新的。
3. 只有改 `dev/src/render.js` 才需要重启（ES module 缓存）。

### `npm run dev` 会自动编译（实测有效）

```
npm run dev   # watch：监听 src/input.css + @source 里的 EJS/JS/HTML，存盘即重编译
```

实测：在 `TimelyBlogTheme.ejs` 里新写一个 `w-[3.5rem]`，**不手动 build**，产物被自动重建、
`.w-\[3\.5rem\]` 自动生成。所以**开发期开着 `npm run dev` 最省事**。

⚠️ `dev` 已带 `--minify`（与 `build` 产物一致）。早期版本漏了 `--minify`，
产物会从 50KB 变成 63KB 未压缩版 —— 若你上传过那种产物，重新 `npm run build` 一下。

## 〇、构建链路（重要）

```
src/input.css  ──npm run build:css──▶  TimelyBlogTheme.css ──┬──▶  Trilium / dev 预览引用
   ↑ 改这里                                                    │      ↑ 产物，别改
   @import tailwindcss source(none) + @source 清单 + @theme 变量 + 手写样式段
                                                               │
TimelyBlogTheme.css + .js  ──npm run dist──▶  dist/timely-theme.css|js  ──▶  上传 CDN
                                                  ↑ 已压缩 + 已按 CDN 改名
```

⚠️ **不要再手改 `TimelyBlogTheme.css`** —— 它是产物，下次 `npm run build` 会整个覆盖。
   要改样式请改 `src/input.css`。
⚠️ **`dist/` 同理** —— 只有 `npm run build` 会刷新它，`npm run dev` 不会。

⚠️ **扫描范围是「白名单」**：`@import "tailwindcss" source(none)` 关掉了自动全域扫描，
   只有 `@source` 列出的文件里的 class 才会被编译。
   **新增模板/脚本文件（或改了文件名）时，必须在 `src/input.css` 补一条 `@source`**，
   否则那个文件里的 class 不会生成、样式静默失效。
   （不关掉自动扫描的后果：`PLAN.md`、本文档、`mockups/*.html` 里当示例写的
   `max-w-[87.5rem]`、`animate-pulse`、`h-20` 也会被当成真实使用，混进生产 CSS。）

| 命令 | 作用 |
|---|---|
| `npm run build` | 完整发布链路：编译 CSS + 压缩打包 → `dist/` |
| `npm run build:css` | 只编译一次 CSS（~100ms） |
| `npm run dev` | 监听 src/input.css 变化，自动重编译（**不刷新 dist/**） |

## 一、宽度：改 1 处就够（变量驱动）

**所有布局联动值已提成 CSS 变量，定义在 `src/input.css` 的 `:root`：**

```css
:root {
  --layout-container: 98rem;   /* 容器总宽 */
  --layout-aside: 340px;       /* 侧栏宽 */
  --layout-top: 6rem;          /* 侧栏顶边 */
}
```

`left` 公式、`max-height` 全部引用这三个变量 → **改一处，全联动**。

### 但 EJS 里还有一份「镜像值」必须同步

CSS 变量控制的是**侧栏的定位**；**正文容器自己**的宽度由 EJS 的 class 决定。
所以改容器总宽要**两边一起改**：

| 改什么 | 改哪里 |
|---|---|
| `--layout-container` | `src/input.css` `:root` |
| EJS 的 `max-w-[98rem]` | EJS **4 处**：`338` `384` `397` `699` |
| `--layout-aside` | `src/input.css` `:root` |
| EJS 的 `w-[340px]` / `grid-cols-[1fr_340px]` | EJS **2 处**：`385` `618` |

改完 `npm run build`。**smoke 有守卫会替你核对两边是否一致**（不等会直接报差多少 px）。

### 宽度对照

| 想要 | `--layout-container` | EJS 的 max-w |
|---|---|---|
| 贴满视口（旧行为） | `100rem` | `max-w-[100rem]` |
| 当前 | `98rem` | `max-w-[98rem]` |
| 两侧各留白 100px | `87.5rem` | `max-w-[87.5rem]` |
| 两侧各留白 160px | `80rem` | `max-w-[80rem]` |

### 侧栏宽 → 正文自动变窄

⚠️ 三处必须**同一个值**：CSS 的 `--layout-aside`、EJS 的 `w-[Npx]`、EJS 的 `grid-cols-[1fr_Npx]`。
   前两者是「侧栏实际宽 / 定位减数」，必须相等；grid 右列若小于 N，正文列会与侧栏**重叠**
   （侧栏是 fixed、不占 grid 位置，右列只是给正文让出的空白）。

| 侧栏宽 N | 正文列宽（容器 1568px，gap 48px） |
|---|---|
| 240px | 1200px |
| 280px | 1160px |
| 300px | 1140px |
| **340px** | **1100px**（当前） |

（正文列宽 = 容器内容区 1488px − N − gap 48px）

⚠️ 想让正文**不变窄**，就同时把容器加大同样的量。

### 列间距

```
EJS  第 383 行   gap-10 xl:gap-12    ← 前=lg(40px) 后=xl(48px)
```
常用：`gap-6`(24) / `gap-8`(32) / `gap-10`(40) / `gap-12`(48) / `gap-16`(64)

## 二、高度

### 1. 正文上下留白

```
EJS  第 382 行  ... px-5 sm:px-8 xl:px-10 py-10 pb-28 md:pb-14
                                              ^^^^^ ^^^^^^^^^^^^^^^
                                              py-10 = 上下各 40px
                                              pb-28 / md:pb-14 = 底部留白（覆盖上方 pb）
```
常用：`py-6`(24) / `py-8`(32) / `py-12`(48) / `py-16`(64)

### 2. 侧栏顶边（`--layout-top`）

```
src/input.css  :root  →  --layout-top: 6rem;
```

推导（**只有两项，别再加"呼吸间距"**）：
```
--layout-top = header h-14(3.5rem/56px) + 容器 py-10(2.5rem/40px) = 6rem(96px)
```

⚠️ 改了 EJS 的 `py-10` → `--layout-top` 必须跟着改。
⚠️ `max-height` 已写成 `calc(100vh - var(--layout-top) - 1.5rem)`，**自动跟随**，不用管。

### 3. 详情页正文顶边（要跟侧栏对齐）

```
EJS  第 394 行  ... pt-0 pb-28 md:pb-14
                    ^^^^
```
⚠️ 详情页正文顶边 = 56(header) + 40(shell py-10) + **这份 pt**
写 `pt-0` → 96px，与侧栏齐（当前）。写回 `py-10` → 136px，会比侧栏低 40px。
⚠️ **水平 `px-5 sm:px-8 xl:px-10` 不能删**，删了正文贴边。

| 两侧卡片内边距 | EJS `465`（左文章卡 `p-5 md:p-6`）与 `616`（右首张卡 `p-5 md:p-6`）—— **两处要一致** |

### 任意值类（如 `max-w-[98rem]`）不用手写 CSS 了

`@source` 已指向 EJS/JS/HTML，Tailwind 会**自动扫描这几个文件并生成**。改 EJS 的 class 名后
`npm run build` 一次即可，产物里就有对应声明。

⚠️ 只扫 `@source` 列出的文件（`source(none)`）—— 在**新文件**里写任意值类，得先补 `@source`。
